# Panel Agent 服务器聊天记录（2.6.0-cloudssh.56）

## 入口与使用

Agent 面板中“对话存储管理”显示保存状态、当前对话归属和摘要覆盖范围。
通过“新对话归属”选择某台已打开的服务器或“通用对话”。新建对话会保留原对话，
不会关闭 SSH。历史面板可搜索标题、查看所有服务器的记录、打开旧对话、改名或删除。
“清空本分类历史”只删除当前登录用户在所选服务器/通用分类中的记录，并需要确认。

恢复旧对话只恢复聊天内容，不自动连接 SSH，也不重新执行历史命令。
需要操作服务器时，在现有终端选择器中选择有权限的终端。一个聊天可包含多个终端的工具结果，
分类归属仍是创建时的主服务器；历史命令中的 targetId 不是可自动恢复的执行授权。

消息存储在应用已有的 SQLite 数据库中，由现有数据库保存/加密机制持久化。
启用默认数据库文件加密时，聊天也随数据库加密保存。备份已有应用数据库和根密钥即可包含聊天。
不要删除或更换现有 Docker 数据挂载；本版不改变卷配置或根密钥。

同一 CloudSSH 账号在其他设备打开同一实例，可通过历史面板加载记录。
本版采用显式刷新/重新打开，不提供多个浏览器同时实时协同编辑。
并发写入冲突会被拒绝，不覆盖另一窗口的历史；先导出本地未保存副本，再重新打开记录。

## 保存与异常恢复

完整的新消息正文、附件内容、模型回复、工具调用及工具返回的终端观察结果独立保存。
读取最近 100 条消息，较早内容通过“加载更早消息”分页读取；列表每页 50 个对话。
“导出完整记录”导出服务器上的全部原始消息和摘要；“导出本地副本”也可在保存失败时使用，
但本地副本只包含当前加载到页面的消息，不能替代完整服务器导出。

用户消息先确认保存再请求模型，模型回复先在服务器保存再返回浏览器，工具执行前后都有保存检查。
保存失败会暂停后续模型/工具轮次，显示错误并允许重试，不会为腾空间自动删除旧记录。
HTTP 丢失确认后的重试使用稳定消息 ID 去重。停止不会撤销已经送入 SSH 的命令。
浏览器被强制关闭或网络断开时，已经执行却未回传的工具结果仍可能缺失；恢复上下文会明确标记
“执行结果未记录”，而不是假定成功或自动重放。该聊天历史不是防篡改安全审计，终端录像仍是独立功能。

## 摘要压缩

“压缩”使用已经配置的模型生成语义摘要；不会删除或替换原始消息。
摘要与近期完整轮次构成后续模型上下文，可在“查看摘要”中检查。
“自动摘要”默认开启，可取消勾选；会使用当前模型并产生模型调用费用。
摘要会有信息损失，重要操作应以原始记录和当前服务器检查为准。

压缩以完整用户/工具轮次为边界，保留最新一轮及至少最近 12 条消息。
一次请求最多处理一批较早轮次，超长终端输出会为摘要输入节选；原始存储不受影响。
很长的历史可能需要多次压缩。自动压缩每个模型轮次最多连续处理 4 批。
若仍有未覆盖历史超过上下文预算，将暂停并提示继续压缩或新建，不静默丢弃历史。
摘要请求不具备工具执行能力。生成失败、摘要为空或期间有其他窗口更新时，不提交新摘要。

## 旧版浏览器记录迁移

在“历史记录”中点击“导入浏览器旧记录”，确认这些旧记录属于当前登录账号。
导入到通用对话，保留原 localStorage 数据；重复导入相同记录不会重复添加消息。
因为旧版记录没有可靠服务器归属，不会把它们擅自分配给某台服务器。
旧版已经裁剪或未存下来的正文/图片无法从服务器找回。
新版正常聊天不再把全部正文写入 localStorage，浏览器只保留原有小型偏好配置。

## 配额、删除与隐私

每个对话最多 64 MiB 原始消息，每个用户最多 256 MiB、2000 个对话；全站聊天原始消息最多 512 MiB。
达到限制会明确报错并停止新增，不自动清理或假装已经保存。需要更大规模时，应另行评估数据库
内存、备份和存储架构，而不是继续扩大浏览器配额。

删除立即从当前数据库移除所选对话及其消息，不能通过聊天历史恢复；既有离线备份不被自动擦除。
用户删除会级联清理聊天。普通用户/管理员均不能通过这些接口读取其他用户的聊天。
查看服务器分类的记录还需当前服务器连接权限；被撤销后，所有者仍能删除自己的记录。

聊天和终端输出可能包含敏感信息。不要在聊天中输入密码/私钥；完整导出文件应妥善保管。
本版不改变现有 JWT、权限、SSH 心跳、安全检查或服务器执行模式。
